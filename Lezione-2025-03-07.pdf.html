Introduction

Welcome to this introductory lesson on Haskell. Haskell is presented as a typeful programming language, where types are pervasive and play a central role. It is a powerful, purely functional language known for its strong type system, lazy evaluation, and elegant syntax. These features make Haskell a popular choice in both academia and industry for a wide range of applications, including web development, financial modeling, and formal verification.

This course will cover the basics of Haskell programming. We will explore fundamental concepts such as:

  • Haskell’s type system in detail.

  • Basic data types.

  • Function definitions.

  • Key features including currying, polymorphism, higher-order functions, and lambda abstractions.

  • Infix operators and sections for writing concise and expressive code.

This lesson is designed for students with some programming experience, particularly those familiar with languages like Java, C, or ML. While prior exposure to functional programming is helpful, it is not required. The transition to Haskell’s type system might require some adjustment, as it is richer and more expressive than those found in many other common languages. However, this richness provides significant benefits in terms of program correctness and expressiveness.

One of Haskell’s powerful features is its ability to perform type inference. The Haskell compiler can automatically infer types, reducing the need for explicit type declarations in many cases. Despite this, including type signatures in your code is considered good practice. Type signatures serve as valuable documentation and help in early error detection by allowing the compiler to verify the correctness of your code against the declared types.

We will start with the fundamental building blocks and progressively develop a comprehensive understanding of Haskell’s core principles.

Haskell’s Type System

Haskell is strongly recognized as a typeful programming language, where types are not just annotations but are fundamental to the language’s structure and behavior. This means that types are pervasive; every expression in Haskell has a type associated with it. The type system in Haskell is instrumental in ensuring program correctness and safety.

For programmers transitioning from languages like Java, C, or even ML, the type system of Haskell might present a learning curve. While some concepts may seem familiar, Haskell’s type system is notably more expressive and richer than those found in many other commonly used programming languages. This richness allows for more robust and reliable software.

Typeful Programming Language

Being a typeful language implies that types are not optional; they are an integral part of the language. This has several significant advantages:

  • Early Error Detection: The type system catches a wide range of errors at compile time, preventing runtime surprises. This is in contrast to dynamically typed languages where many errors are only detected during execution.

  • Improved Code Maintainability: Explicit types act as documentation, making it easier to understand the intended behavior of code, which is crucial for long-term maintainability and collaboration.

  • Enhanced Program Reliability: By enforcing type constraints, Haskell programs are inherently more reliable as type errors, which often lead to unexpected behavior, are largely eliminated before runtime.

While the initial adjustment to a typeful language might require more upfront effort, the benefits in terms of code quality and reduced debugging time are substantial.

Type Inference

One of Haskell’s most celebrated features is type inference. This advanced capability allows the Haskell compiler to automatically deduce the type of expressions without explicit type signatures in many cases. The compiler analyzes how expressions and variables are used within the code and infers their most general types.

For example, if you define a function:

inc x = x + 1

Haskell can infer that inc has the type Integer -> Integer (or more generally, a type involving type classes, which will be discussed later) because the + operator is used with 1, which is an integer literal, and x is added to it.

Despite the power of type inference, it is considered best practice to include type signatures in your Haskell code. Judiciously placed type signatures serve as excellent documentation, clarifying the intended types of functions and values, thereby making the code easier to understand and maintain. Furthermore, type signatures act as a form of specification and can help catch programming errors even earlier. If the inferred type does not match the declared type signature, the compiler will report a type error.

For instance, adding a type signature to our inc function:

inc :: Integer -> Integer
inc x = x + 1

This explicitly states that inc is intended to be a function that takes an Integer and returns an Integer. If the implementation of inc were to violate this type, the compiler would immediately flag it as an error.

In summary, Haskell’s type system, with its powerful type inference and emphasis on explicit type signatures, is a cornerstone of writing robust, maintainable, and correct functional programs.

Values and Types

In Haskell, being a purely functional language, computations are centered around evaluating expressions to produce values. It’s crucial to understand that Haskell operates on values and types.

Purely Functional Language and Values

Haskell’s foundation as a purely functional language dictates that computation is essentially the evaluation of mathematical functions. This paradigm inherently avoids the concepts of mutable state and side effects, which are common in imperative programming. Every action in Haskell is fundamentally an evaluation of an expression.

Expressions are syntactic terms that, when processed by the Haskell runtime, are reduced to values. Values are the abstract results of these computations. Think of values as the final, irreducible forms of expressions, representing the outcome we are interested in.

Crucially, in Haskell, every expression and every value is associated with a type.

Types serve to classify values and expressions based on their kind. They provide a way to reason about the structure and behavior of our programs at compile time, ensuring that operations are applied to appropriate kinds of data.

Type Expressions and Examples of Types

Type expressions are the syntactic representation of types in Haskell. They are terms that denote type values. For brevity, we often use the term "types" when we are actually referring to "type expressions". Haskell comes with a rich set of built-in types and mechanisms to construct more complex types from simpler ones.

Here are some fundamental categories of type expressions with examples:

  • Atomic Types: These are the most basic, indivisible types provided by Haskell.

    • Int: This type represents fixed-precision integers, specifically machine integers. The range of Int is platform-dependent but typically corresponds to the native integer size of your processor.

      • Examples: 5, -10, 0, 42, -100000.

    • Char: Represents single characters, as defined by the Unicode standard.

      • Examples: ’a’, ’B’, ’?’, ’ ’, ’λ’.

    • Bool: Represents boolean values, which can be either true or false.

      • Examples: True, False.

    • Float: Represents single-precision floating-point numbers, as specified by the IEEE standard.

      • Examples: 3.14, -2.0, 0.0, 1.2e6, -0.5.

    • String: Represents sequences of characters. In Haskell, String is actually a synonym for [Char], meaning a list of characters.

      • Example: "hello", "Haskell", "" (the empty string).

  • Function Types: These types describe functions. A function type specifies the type of input(s) and the type of the output.

    • Int -> Char: This is the type of a function that takes a single argument of type Int and returns a value of type Char.

      • Example: A function that converts an integer representing an ASCII code to its corresponding character would have this type.

    • a -> b: This is a polymorphic function type. Here, a and b are type variables. This type represents a function that takes an argument of some type a and returns a value of some type b, where a and b can be any types. This is a powerful concept that allows for writing functions that are generic across many types.

  • Structured Types: These are composite types built from other types. They allow us to represent collections or combinations of data.

    • [Int]: Represents a list where all elements are of type Int. Lists in Haskell are homogeneous, meaning all elements must be of the same type.

      • Examples: [1, 2, 3], [] (the empty list), [5, -5, 0].

    • (Char, Int): Represents a pair, also known as a 2-tuple. This type combines a Char and an Int. Tuples can hold a fixed number of elements of potentially different types.

      • Examples: (’a’, 1), (’z’, 26), (’?’, 0).

    • (Bool, String, Char, Int): Represents a 4-tuple, combining a Bool, a String, a Char, and an Int. Haskell supports tuples of arbitrary finite length.

      • Example: (True, "hello", ’b’, 4).

Type Annotations

In Haskell, we use the double colon :: to assert or declare the type of an expression. This is known as a type annotation. Type annotations have the form expression :: Type.

Here are examples of type annotations using the types we have discussed:

5             :: Int         -- The integer literal 5 has type Int
'a'           :: Char        -- The character literal 'a' has type Char
[1,2,3]       :: [Int]       -- The list [1,2,3] has type list of Int
"hello"       :: String      -- The string literal "hello" has type String
('b', 4)      :: (Char, Int) -- The pair ('b', 4) has type pair of Char and Int
(True, "hello", 'b', 4) :: (Bool, String, Char, Int) -- A 4-tuple with a specified type

The notation expression :: Type is read as "expression has type Type". Type annotations are not just comments; they are checked by the compiler. If the declared type does not match the type inferred by Haskell, a compilation error will occur.

Attention: Haskell’s lexical syntax is case-sensitive, especially concerning type identifiers.

  • Type identifiers must always begin with an uppercase letter. Examples include Int, Char, String, Bool, Float.

  • Identifiers for values and functions should start with a lowercase letter. Examples include add, inc, fact, myValue.

This distinction is crucial and must be adhered to when writing Haskell code to avoid syntax errors.

Polymorphic Types

Haskell’s type system is significantly enhanced by the inclusion of polymorphic types. Polymorphism, in general, allows a single piece of code to work with values of multiple types. In Haskell, we specifically use parametric polymorphism, often just referred to as polymorphism, which is a powerful feature that greatly increases code reusability and flexibility.

Parametric Polymorphism

Definition 1. Parametric polymorphism allows us to write functions and define data structures that are generic over types. Instead of writing separate code for each specific type, we can write one piece of code that operates uniformly on a range of types. This is achieved through the use of type variables in type signatures.

A polymorphic type expression describes a family of types. Consider the example of [a]. This type expression represents the family of "list of t" for every possible type t. Thus, [a] is not a single concrete type, but rather a blueprint for creating types such as:

  • [Int] (list of integers)

  • [Char] (list of characters)

  • [String] (list of strings)

  • [[Int]] (list of lists of integers)

  • and many more...

All of these are instances of the polymorphic type [a]. Here, a is a type variable, acting as a placeholder for any concrete type.

Type variables are identifiers, typically single lowercase letters like a, b, c, etc., used in type expressions to stand for arbitrary types. By convention, they are uncapitalized. When a polymorphic function is used, the type variable is instantiated with a concrete type based on the context of use.

Many of Haskell’s built-in functions and data structures are polymorphic. This is a key reason for Haskell’s expressiveness and the high degree of code reuse it offers. Polymorphism allows us to write functions that are not tied to specific types, making them applicable in a broader range of situations.

For example, consider a function that returns the first element of a list. In Haskell, this is the built-in function head. Its type signature is head :: [a] -> a. Let’s break down what this type signature means:

  • head is the name of the function.

  • :: denotes "has the type".

  • [a] -> a is the polymorphic type signature.

    • [a] indicates that head takes a list as an argument, where the elements of the list are of type a (which can be any type).

    • -> signifies a function type, mapping the input type to the output type.

    • a indicates that head returns a value of the same type a as the elements in the input list.

This polymorphic type signature tells us that head can operate on a list of integers, a list of characters, or a list of any other type, and it will always return an element of that same type.

List Notation and Polymorphism in Practice

In Haskell, the convenient list notation [1,2,3] is actually syntactic sugar. It is a more readable way of writing the expression 1:(2:(3:[])). Understanding this desugaring is crucial for grasping how lists are constructed and how polymorphism applies to them. Let’s dissect this:

  • [] represents the empty list. Its type is [a], which is a polymorphic list type. This means the empty list can be considered a list of any type. It’s the base case for list construction.

  • : is the cons operator (short for "construct"). It is an infix operator in Haskell, pronounced "cons". The cons operator is fundamental for building lists. Its type is a -> [a] -> [a]. This type signature is also polymorphic:

    • a is the type of the element to be added to the front of the list.

    • [a] (the second argument) is the type of the list to which the element is prepended.

    • [a] (the result type) is the type of the new list created after prepending the element.

Therefore, the expression x : xs takes an element x of type a and a list xs of type [a], and it returns a new list of type [a] with x at the beginning, followed by the elements of xs.

Let’s illustrate with examples:

  • 1 : [] results in [1], a list of integers. Here, a is instantiated to Int.

  • ’a’ : [’b’, ’c’] results in [’a’, ’b’, ’c’], a list of characters. Here, a is instantiated to Char.

  • True : [False] results in [True, False], a list of booleans. Here, a is instantiated to Bool.

The list [1, 2, 3] is thus constructed step-by-step:

  1. Start with the empty list: [] (which is of type [a])

  2. Prepend 3: 3 : [] results in [3] (of type [Int])

  3. Prepend 2: 2 : [3] results in [2, 3] (of type [Int])

  4. Prepend 1: 1 : [2, 3] results in [1, 2, 3] (of type [Int])

Consider again the head and tail functions we saw earlier:

head :: [a] -> a
head (x:xs) = x

tail :: [a] -> [a]
tail (x:xs) = xs

These functions utilize pattern matching on the list structure. The pattern (x:xs) matches any non-empty list, binding x to the first element (head) and xs to the rest of the list (tail).

Example 1. Examples of polymorphic behavior of head and tail:

  • head [1, 2] is evaluated as head (1:(2:[])), which matches the pattern (x:xs) with x = 1 and xs = [2]. It returns x, which is 1 (an Int).

  • tail [1, 2] is evaluated as tail (1:(2:[])), which again matches (x:xs) with x = 1 and xs = [2]. It returns xs, which is [2] (a list of Int, i.e., [Int]).

The polymorphism of head and tail is evident as they operate seamlessly on lists of any type, always adhering to their polymorphic type signatures. This exemplifies the power and elegance of parametric polymorphism in Haskell.

Functions

Functions are fundamental building blocks in Haskell. In Haskell, functions are defined primarily through equations. A set of these equations constitutes a function declaration.

Function Declarations

Function declarations in Haskell specify how a function behaves for different inputs. Let’s look at some examples to understand how functions are declared.

Increment Function

Example 2. To define a function named inc that increments a number by one, we write:

inc x = x + 1

This single equation is a complete function declaration for inc. It states that when inc is applied to an argument x, the result is the value of x + 1.

Factorial Function

Example 3. For a more complex example, consider the factorial function. The factorial function is typically defined recursively. In Haskell, we can define it using multiple equations to handle different cases:

fact 0 = 1
fact n = n * fact (n-1)

This declaration consists of two equations:

  • The first equation, fact 0 = 1, is the base case. It specifies that the factorial of 0 is 1.

  • The second equation, fact n = n * fact (n-1), is the recursive case. It defines the factorial of any number n (implicitly assumed to be positive in this context) as n multiplied by the factorial of n-1.

When fact is called, Haskell will try to match the input with the equations in the order they are written. If the input is 0, the first equation is matched, and the result is 1. If the input is any other number n, the second equation is matched, and the factorial is computed recursively.

Combination Function

Example 4. As another example, let’s define a function to calculate combinations, often denoted as "n choose k", which is the number of ways to choose k items from a set of n items. Mathematically, it’s given by \(\binom{n}{k} = \frac{n!}{k!(n-k)!}\). Assuming we have already defined the factorial function fact, we can define a combination function comb as:

comb n k = fact n `div` fact k `div` fact (n-k)

In this definition, ‘div‘ is used for integer division in Haskell and is used in infix notation by enclosing it in backticks. This equation directly implements the mathematical formula for combinations using the fact function.

Type Signature Declarations

While Haskell’s type inference can often deduce the types of functions, it is excellent practice to explicitly declare the types of functions using type signature declarations. A type signature declaration specifies the type of a function, making the code more readable and helping to catch type errors at compile time.

For the inc and fact functions defined above, we can add type signatures as follows:

inc  :: Int -> Int
inc x = x + 1

fact :: Int -> Int
fact 0 = 1
fact n = n * fact (n-1)

The line inc :: Int -> Int is a type signature declaration for inc. It states that inc is a function that takes an argument of type Int and returns a result of type Int. Similarly, fact :: Int -> Int declares that fact is also a function from Int to Int.

Type signatures are not mandatory in many cases due to Haskell’s type inference, but they are highly recommended for:

  • Documentation: Type signatures clearly communicate the intended type of a function, making it easier to understand the function’s purpose and usage.

  • Error Detection: If the implemented function does not conform to its declared type signature, the Haskell compiler will report a type error. This helps in catching mistakes early in the development process.

  • Clarity in Complex Types: For functions with more complex types, especially higher-order functions or polymorphic functions, type signatures can significantly improve readability.

By using type signatures, you make your Haskell code more robust, maintainable, and easier to understand for yourself and others.

Curried and Uncurried Functions

In Haskell, understanding the concept of curried versus uncurried functions is crucial. By default, functions in Haskell are curried, a design choice that profoundly influences how functions are defined and applied.

Curried Functions

Definition 2. Consider the following definition of a function add that sums two numbers:

add :: Int -> Int -> Int
add x y = x + y

This is the curried form of the add function. The type signature Int -> (Int -> Int) reveals its curried nature. It indicates that add is a function that takes an Int and returns another function (Int -> Int). This returned function then takes an Int and finally returns an Int as the result.

In practice, when we apply add to two arguments, say 5 and 3, the process unfolds as follows:

  1. Partial Application: Applying add to just the first argument, 5, i.e., add 5, does not compute the final sum. Instead, it returns a new function. This new function is specialized to add 5 to its argument. The type of (add 5) is Int -> Int.

  2. Second Application: This new function is then applied to the second argument, 3, i.e., (add 5) 3. This completes the computation, resulting in 8.

Thus, a curried function processes its arguments one at a time, returning a new function at each step until all arguments are provided, at which point it computes the final value. This approach is fundamental to functional programming and enables powerful techniques like partial application and function composition.

Uncurried Functions

Definition 3. In contrast to curried functions, uncurried functions take all their arguments at once, typically as a tuple. We can define an uncurried version of the addition function as:

add' :: (Int, Int) -> Int
add' (x,y) = x + y

Here, the type signature (Int, Int) -> Int clearly shows that add’ takes a single argument, which is a pair (Int, Int). When we call add’, we must provide a pair: add’ (5, 3), which directly returns 8.

The key difference is that add’ expects both numbers to be provided as a single tuple argument, whereas add accepts them sequentially, enabling partial application.

Function Application and Type Constructor Associativity

Understanding associativity is crucial for correctly interpreting Haskell syntax, especially function application and type signatures.

Function Application: Left-Associative

Remark. Remark 1. Function application in Haskell is left-associative. This means that when you have a sequence of function applications like f e1 e2 e3, it is parsed as if parenthesized from the left: ((f e1) e2) e3.

For example, with our curried add function, add 5 3 is interpreted as (add 5) 3. First, add is applied to 5, resulting in a function (add 5). Then, this resulting function is applied to 3.

Function Type Constructor: Right-Associative

Remark. Remark 2. In contrast, the function type constructor -> is right-associative. This affects how type signatures are parsed. A type like Int -> Int -> Int is parsed as Int -> (Int -> Int).

This right-associativity is consistent with the concept of currying. Int -> Int -> Int represents a function that takes an Int and returns a function of type Int -> Int, which in turn takes an Int and returns an Int.

Summary of Associativity:

  • Function Application is left-associative: f e1 e2 \(\equiv\) (f e1) e2

  • Function Type Constructor (->) is right-associative: T1 -> T2 -> T3 \(\equiv\) T1 -> (T2 -> T3)

This combination of left-associativity for application and right-associativity for the type constructor is what makes currying a natural and seamless feature of Haskell.

Examples of Polymorphic Functions

To solidify our understanding of polymorphic types, let”s explore some built-in Haskell functions that exemplify polymorphism in action. We will look at the functions head, tail, and length, all of which operate on lists but are not restricted to lists of a specific type.

head :: [a] -> a
head (x:xs) = x

tail :: [a] -> [a]
tail (x:xs) = xs

length :: [a] -> Int
length []     = 0
length (x:xs) = 1 + length xs

Polymorphism in Type Signatures

Observe the type signatures of these functions. Each of them includes the type variable a within their type definitions, making them polymorphic. This means they are not limited to operating on lists of integers, characters, or any other single specific type; they can work with lists containing elements of any type.

  • head :: [a] -> a: This signature indicates that head is a function that takes a list of type [a] (a list of elements of some type a) and returns a single element of type a. The crucial point is that a can be any type.

  • tail :: [a] -> [a]: Similarly, tail takes a list of type [a] and returns another list of type [a]. It returns the remainder of the list after removing the first element, maintaining the element type.

  • length :: [a] -> Int: The length function takes a list of type [a] and returns an Int. It counts the number of elements in the list, irrespective of the element type.

Pattern Matching in Function Definitions

The function definitions themselves utilize pattern matching on the structure of lists. Pattern matching is a powerful feature in Haskell that allows functions to be defined by cases based on the form oftheir input arguments.

Let’s break down the patterns used:

  • []: This pattern matches specifically against the empty list. In the definition of length, length [] = 0 states that when length is applied to an empty list, it returns 0.

  • (x:xs): This pattern matches against non-empty lists. It deconstructs a non-empty list into two parts:

    • x: Bound to the head (the first element) of the list.

    • xs: Bound to the tail (the rest of the list, which is itself a list) of the list.

    In head (x:xs) = x, when head is applied to a non-empty list, it matches this pattern, and the function returns x, the head of the list. Similarly, tail (x:xs) = xs returns xs, the tail of the list. For length (x:xs) = 1 + length xs, it recursively calculates the length by adding 1 (for the head element x) to the length of the tail xs.

Illustrative Examples

Let’s see these polymorphic functions in action with different types of lists:

  • Using head

    • head [1, 2] : Here, head is applied to a list of integers. The list [1, 2] matches the pattern (x:xs) with x bound to 1 and xs bound to [2]. The function returns x, which is 1. Thus, head [1, 2] evaluates to 1.

    • head\['a', 'b', 'c'\] : Applied to a list of characters, head still works. x becomes ’a’ and xs becomes [’b’, ’c’]. head\['a', 'b', 'c'\] evaluates to ’a’.

  • Using tail

    • tail [1, 2] : For the integer list, tail returns the rest of the list after the head. tail [1, 2] evaluates to [2].

    • tail\['a', 'b', 'c'\] : For the character list, tail similarly returns the tail. tail\['a', 'b', 'c'\] evaluates to [’b’, ’c’].

  • Using length

    • length [1, 2, 3, 4] : Counts the elements in the integer list. length [1, 2, 3, 4] evaluates to 4.

    • length\["apple", "banana", "cherry"\] : Counts the elements in a list of strings. length\["apple", "banana", "cherry"\] evaluates to 3.

    • length [] : For the empty list, it matches the [] pattern and returns 0. length [] evaluates to 0.

These examples demonstrate that head, tail, and length are indeed polymorphic. They operate uniformly on lists regardless of the type of elements contained within them, adhering to their respective polymorphic type signatures. This exemplifies the power and elegance of parametric polymorphism in Haskell.

Higher-Order Functions

Definition 4 (Higher-Order Functions). Higher-order functions are a distinguishing feature of functional programming languages like Haskell. They are functions that operate on other functions, either by taking one or more functions as arguments or by returning a function as a result. This capability elevates functions to first-class citizens in the language, allowing for powerful abstractions and code reuse.

In Haskell, curried functions are inherently higher-order because when you partially apply a curried function, you get another function as a result.

Let’s explore some fundamental higher-order functions in Haskell: map, foldr, and foldl.

map :: (a -> b) -> [a] -> [b]
map f []     = []
map f (x:xs) = f x : map f xs

foldr :: (a -> b -> b) -> b -> [a] -> b
foldr f z (x:xs) = f x (foldr f z xs)
foldr f z []     = z

foldl :: (b -> a -> b) -> b -> [a] -> b
foldl f z (x:xs) = foldl f (f z x) xs
foldl f z []     = z

The map Function

Definition 5 (The map Function). The map function is used to apply a given function to each element of a list, producing a new list containing the results.

Type Signature and Definition

map :: (a -> b) -> [a] -> [b]

  • (a -> b): The first argument is a function, let’s call it f, that takes a value of type a and returns a value of type b.

  • [a]: The second argument is a list of type [a], i.e., a list of elements of type a.

  • [b]: The return type is a list of type [b], a list of elements of type b.

The definition of map is given by two equations, again using pattern matching:

map f []     = []
map f (x:xs) = f x : map f xs

  • Base Case: map f [] = [] - When map is applied to an empty list ( [] ), it returns an empty list. This is the terminating condition for the recursion.

  • Recursive Step: map f (x:xs) = f x : map f xs - When map is applied to a non-empty list (x:xs), it does two things:

    1. Applies the function f to the head element x to get f x.

    2. Recursively calls map f xs to process the rest of the list xs.

    3. Constructs a new list by prepending (f x) to the result of the recursive call (map f xs) using the cons operator :.

Example Usage of map

Let’s define a simple increment function inc:

inc x = x + 1

Now, let’s use map with inc to increment every element in a list of numbers:

expression: map inc [1,2,3]

This expression evaluates to [2,3,4]. Here’s how it works step-by-step:

  1. map inc [1, 2, 3]

  2. inc 1 : map inc [2, 3] (applying the recursive step)

  3. 2 : map inc [2, 3] ( inc 1 evaluates to 2 )

  4. 2 : (inc 2 : map inc [3]) (recursive step again)

  5. 2 : (3 : map inc [3]) ( inc 2 evaluates to 3 )

  6. 2 : (3 : (inc 3 : map inc [])) (one more recursive step)

  7. 2 : (3 : (4 : map inc [])) ( inc 3 evaluates to 4 )

  8. 2 : (3 : (4 : [])) ( map inc [] evaluates to [] - base case)

  9. [2, 3, 4] (list construction)

The foldl Function (Fold Left)

Definition 6 (The foldl Function). The foldl function, short for "fold left", is another powerful higher-order function used to combine the elements of a list into a single value. It does this by applying a binary function cumulatively from left to right.

Type Signature and Definition

foldl :: (b -> a -> b) -> b -> [a] -> b

  • (b -> a -> b): The first argument is a binary function, let’s call it f, that takes two arguments: an accumulator of type b and an element of type a, and returns a new accumulator of type b.

  • b: The second argument is the initial value of the accumulator, often called the "base case" or "zero case", of type b.

  • [a]: The third argument is the input list of type [a].

  • b: The return type is the final accumulated value of type b.

The definition of foldl is:

foldl f z (x:xs) = foldl f (f z x) xs
foldl f z []     = z

  • Base Case: foldl f z [] = z - When foldl is applied to an empty list, it returns the initial accumulator value z.

  • Recursive Step: foldl f z (x:xs) = foldl f (f z x) xs - For a non-empty list (x:xs), foldl does the following:

    1. Applies the binary function f to the current accumulator z and the head element x to get a new accumulator (f z x).

    2. Recursively calls foldl with the new accumulator (f z x) and the tail of the list xs.

Example Usage of foldl

Let’s use foldl to sum the elements of a list, starting with an initial sum of 10. We’ll assume add is our curried addition function from before.

expression: foldl add 10 [1,2,3]

This expression evaluates to 16. Let’s trace the evaluation:

  1. foldl add 10 [1, 2, 3]

  2. foldl add (add 10 1) [2, 3] (apply add to initial accumulator 10 and head 1)

  3. foldl add (10 + 1) [2, 3] (evaluate add 10 1 to 11)

  4. foldl add 11 [2, 3] (simplified accumulator)

  5. foldl add (add 11 2) [3] (apply add to current accumulator 11 and head 2)

  6. foldl add (11 + 2) [3] (evaluate add 11 2 to 13)

  7. foldl add 13 [3] (simplified accumulator)

  8. foldl add (add 13 3) [] (apply add to current accumulator 13 and head 3)

  9. foldl add (13 + 3) [] (evaluate add 13 3 to 16)

  10. foldl add 16 [] (simplified accumulator)

  11. 16 (base case: empty list, return current accumulator 16)

Thus, foldl add 10 [1, 2, 3] results in 16, which is 10 + 1 + 2 + 3.

The foldr Function (Fold Right)

Definition 7 (The foldr Function). The foldr function, or "fold right", is similar to foldl but it processes the list from right to left. It’s often more conceptually aligned with recursive list processing in functional programming.

Type Signature and Definition

foldr :: (a -> b -> b) -> b -> [a] -> b The type signature of foldr is the same as foldl, but its behavior is different.

foldr f z (x:xs) = f x (foldr f z xs)
foldr f z []     = z

  • Base Case: foldr f z [] = z - Just like foldl, for an empty list, foldr returns the initial value z.

  • Recursive Step: foldr f z (x:xs) = f x (foldr f z xs) - For a non-empty list (x:xs), foldr does:

    1. Recursively calls foldr f z xs on the tail xs to process the rest of the list first. Let’s say the result of this recursive call is recursive_result.

    2. Applies the binary function f to the head element x and the recursive_result to get the final result (f x recursive_result).

Notice how in foldr, the function f is applied to the current element x and the result of folding the rest of the list, contrasting with foldl where f is applied to the accumulator and the current element.

Remark. Remark 3 (Conceptual Difference between foldl and foldr).

Conceptual Difference between foldl and foldr

  • foldl is typically iterative in nature, accumulating a result from left to right. It’s often more efficient in strict languages for simple accumulations but can be less efficient with lazy evaluation for certain operations.

  • foldr is more naturally recursive and works from right to left. It’s particularly well-suited for operations that can benefit from lazy evaluation and for preserving list structure in transformations. For many operations in Haskell, foldr is considered more idiomatic and sometimes more efficient due to laziness.

Summary

Higher-order functions like map, foldl, and foldr are essential tools in functional programming. They allow for abstracting common patterns of computation over lists and other data structures, leading to more concise, reusable, and expressive code. Understanding and effectively using these functions is a key step in mastering functional programming in Haskell.

Partial Application of Curried Functions

Definition 8 (Partial Application). One of the most powerful features enabled by currying in Haskell is partial application. Partial application allows you to apply a function to fewer arguments than it is designed to accept. The result is a new function that is waiting for the remaining arguments. This technique is incredibly useful for creating specialized functions from more general ones and for enhancing code conciseness and readability.

Basic Partial Application

Example 5 (Basic Partial Application of add function). Consider our familiar curried addition function, add:

add :: Int -> Int -> Int
add x y = x + y

We can create a new function, say inc, which increments a number by one, by partially applying add with the first argument set to 1:

inc = add 1

Here, inc is not a value but a function. By providing only the first argument (1) to add, we’ve created a specialized version of add. The function inc now has the type Int -> Int. It’s a function that is "waiting" for one more Int argument to complete the addition.

When we call inc with an argument, say 5:

inc 5

This is equivalent to (add 1) 5, which then evaluates to 1 + 5 = 6.

Partial Application with Higher-Order Functions

Example 6 (Partial Application with Higher-Order Functions (map)). Partial application becomes even more potent when combined with higher-order functions. Let’s revisit the map function:

map :: (a -> b) -> [a] -> [b]

Suppose we want to increment every number in a list by 1. Instead of defining a separate named function and then using map, we can directly use partial application with add within map:

map (add 1) [1,2,3]

This elegantly applies the "increment by 1" operation to each element of the list [1,2,3]. The expression (add 1) is a partially applied function, which is then passed as the first argument to map. map then applies this partially applied function to each element of the list, resulting in [2,3,4].

Example with Combination Function

Example 7 (Partial Application with Combination Function). Let’s consider the combination function comb we defined earlier:

comb n k = fact n `div` fact k `div` fact (n-k)

Suppose we want to calculate the number of combinations when choosing k items from a fixed set of 4 items, for various values of k. We can create a function that is specialized for n = 4 by partially applying comb:

combFrom4 = comb 4

Now, combFrom4 is a function of type Int -> Int. It takes one argument k and calculates "4 choose k". We can use this partially applied function with map to calculate combinations for a range of k values:

map combFrom4 [0,1,2,3,4]

or more directly, without defining combFrom4:

map (comb 4) [0,1,2,3,4]

This expression evaluates to [1, 4, 6, 4, 1], which are the binomial coefficients \(\binom{4}{0}, \binom{4}{1}, \binom{4}{2}, \binom{4}{3}, \binom{4}{4}\).

Remark. Remark 4 (Benefits of Partial Application).

Benefits of Partial Application

  • Code Reusability: Create specialized functions from general ones, avoiding redundant code.

  • Readability: Express complex operations more clearly by breaking them down into simpler, partially applied functions.

  • Flexibility: Easily adapt functions to different contexts by fixing some arguments and leaving others open.

  • Composition: Facilitates function composition and point-free style programming, leading to more elegant and concise code.

Partial application is a cornerstone of functional programming in Haskell, enabling a highly flexible and expressive coding style. It encourages building programs by composing and specializing functions, leading to more modular and maintainable code.

Lambda Abstractions

Definition 9 (Lambda Abstractions). In Haskell, functions are not only defined and named but can also be expressed as anonymous entities directly within expressions. This is achieved through lambda abstractions. Lambda abstractions are essentially unnamed functions, defined inline where they are needed. They are a powerful tool for creating functions on-the-fly, especially for higher-order functions.

Syntax and Basic Examples

The syntax for a lambda abstraction in Haskell is:

\arguments -> body

Here:

  • \ (backslash) symbol initiates a lambda abstraction. It’s used because it resembles the Greek letter lambda (λ), which is traditionally used in lambda calculus to denote anonymous functions.

  • arguments is a space-separated list of argument names. These are the parameters of the anonymous function.

  • -> separates the arguments from the function body.

  • body is the expression that defines the function’s computation. It’s the code that will be executed when the anonymous function is applied.

Example 8 (Basic Examples of Lambda Abstractions). Let’s look at some examples to illustrate lambda abstractions:

  • Function to add 3 to its argument:

        \x -> x + 3

    This lambda abstraction defines a function that takes one argument, named x, and returns the result of x + 3. It’s an anonymous equivalent to writing a named function like add3 x = x + 3.

  • Curried function to add two arguments:

        \x -> \y -> x + y

    This defines a curried function that takes two arguments. It’s a lambda abstraction that, when given an argument x, returns another lambda abstraction \y -> x + y. This inner lambda abstraction takes an argument y and returns x + y. This is equivalent to our named curried add function.

  • Concise syntax for curried functions:

        \x y -> x + y

    Haskell provides a more concise syntax for curried lambda abstractions with multiple arguments. \x y -> x + y is equivalent to \x -> \y -> x + y. It’s a shorthand for defining curried functions that take multiple arguments.

Usage with Higher-Order Functions

Example 9 (Usage of Lambda Abstractions with Higher-Order Functions (map)). Lambda abstractions are particularly useful when you need to pass a simple, often one-time-use function as an argument to a higher-order function. They eliminate the need to define a separate named function in such cases, making the code more compact and focused.

Consider using map to multiply each element in a list by 3. Instead of defining a separate function like multiplyBy3 and then passing it to map, we can use a lambda abstraction directly:

map (\x -> 3*x) [1,2,3]

In this expression, (\x -> 3*x) is a lambda abstraction. It’s an anonymous function that takes an argument x and returns 3*x. This anonymous function is directly passed as the first argument to map. map then applies this function to each element of the list [1,2,3], resulting in [3,6,9].

Remark. Remark 5 (Advantages of Lambda Abstractions).

Advantages of Lambda Abstractions

  • Anonymity: Define functions without needing to name them, which is useful for functions that are used only once or in a localized context.

  • Inline Function Definition: Define functions directly within expressions, making the code more concise and often more readable by keeping related code together.

  • Flexibility with Higher-Order Functions: Easily create and pass function arguments to higher-order functions without clutteringthe code with many auxiliary named function definitions.

  • Expressiveness: Enhance the expressiveness of Haskell code by allowing functions to be treated as first-class, inline values.

Lambda abstractions are a vital feature in Haskell and functional programming in general. They promote a style of programming where functions are treated as values that can be created, passed around, and used just like any other data, leading to more flexible and expressive code.

Infix Operators

Definition 10 (Infix Operators). In Haskell, operators like +, *, :, ++, and . are not special syntactic constructs but are actually just functions. The term "infix" refers to their syntactic placement between their operands, as opposed to prefix functions which appear before their arguments. This infix notation is primarily for convenience and readability, especially for operations that are naturally binary.

Operators as Functions

In Haskell, almost anything that looks like an operator is indeed a function. This means that infix operators can be defined and used just like any other function. They can be defined using equations, and they have types.

Example: List Concatenation Operator ++

Example 10 (List Concatenation Operator ++). The list concatenation operator ++ is a prime example. It’s used to join two lists together. We can define its behavior using equations, just like any other function:

[]     ++ ys = ys
(x:xs) ++ ys = x : (xs ++ ys)

These equations define how ++ behaves:

  • When the first list is empty ([]), concatenating it with any list ys results in ys itself (the first equation).

  • When the first list is non-empty (x:xs), concatenating it with ys results in a new list that starts with the head x of the first list, followed by the concatenation of the tail xs and the list ys (the second equation, which is recursive).

This definition is no different from how we might define any other recursive function in Haskell. The only distinction is that ++ is used as an infix operator.

Example: Function Composition Operator .

Example 11 (Function Composition Operator .). Another crucial operator in functional programming is the function composition operator . (dot). It’s used to compose two functions, meaning applying one function to the result of another. Its definition is:

f . g = \x -> f (g x)

This equation defines the composition of two functions f and g. (f . g) results in a new function (a lambda abstraction) that takes an argument x, applies g to x first, and then applies f to the result of (g x).

Lexical Nature of Infix Operators

Remark. Remark 6 (Lexical Nature of Infix Operators). Lexically, infix operators in Haskell are typically distinguished by being composed entirely of symbols, rather than alphanumeric characters. Common symbols used in operators include:

+, -, *, /, $, !, @, %, ^, &, |, <, >, =, ?, ., :, ++, **, >>, <<, ...

For instance, +, *, ++, ::, ., $ are all infix operators. Identifiers composed of letters and digits, typically starting with a lowercase letter, are usually treated as prefix function names.

Using Operators as Prefix Functions

Since operators are functions, and functions in Haskell are first-class, we can also use operators in a prefix manner, just like regular functions. To do this, we enclose the operator in parentheses.

For example, + is an infix operator for addition. Infix usage: 3 + 4. Prefix usage: (+) 3 4. Both expressions are equivalent and evaluate to 7.

This prefix notation is particularly useful when you want to pass an operator as an argument to a higher-order function, or when you want to partially apply an operator. For example, to increment every element in a list using map and the addition operator, you can write:

map ((+) 1) [1,2,3]  -- Evaluates to [2,3,4]

Here, ((+) 1) is a partial application of the prefix version of the + operator. It creates a function that adds 1 to its argument.

Custom Infix Operators

Remark. Remark 7 (Custom Infix Operators). Haskell allows you to define your own infix operators. You can create new operators composed of symbols and define their precedence and associativity if needed (though we won’t delve into precedence and associativity rules here). Defining custom operators can be useful for creating domain-specific languages or for mathematical or symbolic computations where infix notation is conventional and enhances readability.

In summary, infix operators in Haskell are simply functions with a special syntax that allows them to be placed between their operands. They are defined and used just like prefix functions, offering flexibility in how you express operations, especially in mathematical and list-processing contexts.

Sections

Definition 11 (Sections). Sections in Haskell provide a concise syntax for partially applying infix operators. Since infix operators are just functions, sections allow us to create new functions by fixing one of the arguments of an operator, making them very handy, especially when working with higher-order functions.

There are three main types of sections: left sections, right sections, and operator sections.

Left Sections

Definition 12 (Left Sections). A left section is created by enclosing an infix operator and its left operand in parentheses. The syntax is (left_operand operator). This form creates a function that takes one argument (the right operand) and applies the operator with the specified left operand and the given operator.

Example: Incrementing by a Fixed Value

Example 12 (Left Section Example: Incrementing by a Fixed Value). Consider the addition operator +. A left section (5+) is equivalent to the lambda abstraction \y -> 5 + y. It’s a function that takes an argument y and adds 5 to it. In essence, the left operand (5) is fixed, and the section is waiting for the right operand.

(5+) :: Num a => a -> a
(5+) y = 5 + y

We can use this section with map to add 5 to each element of a list:

map (5+) [1, 2, 3]  -- Evaluates to [6, 7, 8]

Right Sections

Definition 13 (Right Sections). A right section is formed by enclosing an infix operator and its right operand in parentheses, like (operator right_operand). This creates a function that takes one argument (the left operand) and applies the operator with the given right operand.

Example: Dividing by a Fixed Value

Example 13 (Right Section Example: Dividing by a Fixed Value). Using the division operator /, a right section (/2) is equivalent to \x -> x / 2. This function takes an argument x and divides it by 2. Here, the right operand (2) is fixed, and the section is waiting for the left operand.

(/2) :: Fractional a => a -> a
(/2) x = x / 2

Example usage:

map (/2) [4, 6, 8]  -- Evaluates to [2.0, 3.0, 4.0]

Operator Sections

Definition 14 (Operator Sections). An operator section consists of just the infix operator enclosed in parentheses, like (operator). This form is used to treat a binary operator as a prefix function. It’s equivalent to a lambda abstraction that takes two arguments and applies the operator to them.

Example: Using Addition as a Prefix Function

Example 14 (Operator Section Example: Using Addition as a Prefix Function). The operator section (+) is equivalent to \x y -> x + y. It represents the binary addition operation as a standard prefix function.

(+) :: Num a => a -> a -> a
(+) x y = x + y

This is particularly useful when you need to pass a binary operator to a higher-order function that expects a function argument. For instance, using foldl to sum up a list of numbers:

foldl (+) 0 [1, 2, 3, 4]  -- Evaluates to 10

Here, (+) is passed as the combining function to foldl.

Coercing Binary Functions to Infix Operators

Remark. Remark 8 (Coercing Binary Functions to Infix Operators). Conversely, if you have a binary function and you want to use it as an infix operator, Haskell allows you to enclose the function name in backquotes (“).

For example, if we have a function myAdd:

myAdd :: Int -> Int -> Int
myAdd x y = x + y

We can use it in infix form like this:

5 `myAdd` 3  -- Equivalent to myAdd 5 3, evaluates to 8

This backtick notation is handy for using named binary functions in an infix style, which can sometimes improve readability, especially in mathematical or domain-specific contexts.

Use Cases for Sections

Remark. Remark 9 (Use Cases for Sections). Sections are incredibly useful in various scenarios:

  • Concise Partial Application: They provide a compact way to create partially applied functions from operators.

  • Higher-Order Functions: Sections are frequently used when passing operators as arguments to higher-order functions like map, filter, foldl, foldr, etc., leading to cleaner and more readable code.

  • Readability: For common operations, sections often make the intent of the code clearer and more immediate than using lambda abstractions.

In summary, sections are a syntactic convenience in Haskell that leverages the fact that operators are functions, allowing for elegant partial application and enhancing the expressiveness of functional code, especially when working with operators and higher-order functions.

# Haskell's Type System

Haskell is strongly recognized as a **typeful programming language**,
where types are not just annotations but are fundamental to the
language's structure and behavior. This means that types are pervasive;
every expression in Haskell has a type associated with it. The type
system in Haskell is instrumental in ensuring program correctness and
safety.

For programmers transitioning from languages like Java, C, or even ML,
the type system of Haskell might present a learning curve. While some
concepts may seem familiar, Haskell's type system is notably more
expressive and richer than those found in many other commonly used
programming languages. This richness allows for more robust and reliable
software.

## Typeful Programming Language

Being a typeful language implies that types are not optional; they are
an integral part of the language. This has several significant
advantages:

-   **Early Error Detection**: The type system catches a wide range of
    errors at compile time, preventing runtime surprises. This is in
    contrast to dynamically typed languages where many errors are only
    detected during execution.

-   **Improved Code Maintainability**: Explicit types act as
    documentation, making it easier to understand the intended behavior
    of code, which is crucial for long-term maintainability and
    collaboration.

-   **Enhanced Program Reliability**: By enforcing type constraints,
    Haskell programs are inherently more reliable as type errors, which
    often lead to unexpected behavior, are largely eliminated before
    runtime.

While the initial adjustment to a typeful language might require more
upfront effort, the benefits in terms of code quality and reduced
debugging time are substantial.

## Type Inference

One of Haskell's most celebrated features is **type inference**. This
advanced capability allows the Haskell compiler to automatically deduce
the type of expressions without explicit type signatures in many cases.
The compiler analyzes how expressions and variables are used within the
code and infers their most general types.

For example, if you define a function:

    inc x = x + 1

Haskell can infer that `inc` has the type `Integer -> Integer` (or more
generally, a type involving type classes, which will be discussed later)
because the `+` operator is used with `1`, which is an integer literal,
and `x` is added to it.

Despite the power of type inference, it is considered best practice to
include **type signatures** in your Haskell code. Judiciously placed
type signatures serve as excellent documentation, clarifying the
intended types of functions and values, thereby making the code easier
to understand and maintain. Furthermore, type signatures act as a form
of specification and can help catch programming errors even earlier. If
the inferred type does not match the declared type signature, the
compiler will report a type error.

For instance, adding a type signature to our `inc` function:

    inc :: Integer -> Integer
    inc x = x + 1

This explicitly states that `inc` is intended to be a function that
takes an `Integer` and returns an `Integer`. If the implementation of
`inc` were to violate this type, the compiler would immediately flag it
as an error.

In summary, Haskell's type system, with its powerful type inference and
emphasis on explicit type signatures, is a cornerstone of writing
robust, maintainable, and correct functional programs.

# Values and Types

In Haskell, being a purely functional language, computations are
centered around evaluating expressions to produce values. It's crucial
to understand that Haskell operates on **values** and **types**.

## Purely Functional Language and Values

Haskell's foundation as a **purely functional language** dictates that
computation is essentially the evaluation of mathematical functions.
This paradigm inherently avoids the concepts of mutable state and side
effects, which are common in imperative programming. Every action in
Haskell is fundamentally an evaluation of an **expression**.

**Expressions** are syntactic terms that, when processed by the Haskell
runtime, are reduced to **values**. **Values** are the abstract results
of these computations. Think of values as the final, irreducible forms
of expressions, representing the outcome we are interested in.

Crucially, in Haskell, every expression and every value is associated
with a **type**.

**Types** serve to classify values and expressions based on their kind.
They provide a way to reason about the structure and behavior of our
programs at compile time, ensuring that operations are applied to
appropriate kinds of data.

## Type Expressions and Examples of Types

**Type expressions** are the syntactic representation of types in
Haskell. They are terms that denote type values. For brevity, we often
use the term \"types\" when we are actually referring to \"type
expressions\". Haskell comes with a rich set of built-in types and
mechanisms to construct more complex types from simpler ones.

Here are some fundamental categories of type expressions with examples:

-   **Atomic Types**: These are the most basic, indivisible types
    provided by Haskell.

    -   `Int`: This type represents fixed-precision integers,
        specifically machine integers. The range of `Int` is
        platform-dependent but typically corresponds to the native
        integer size of your processor.

        -   **Examples**: `5`, `-10`, `0`, `42`, `-100000`.

    -   `Char`: Represents single characters, as defined by the Unicode
        standard.

        -   **Examples**: `’a’`, `’B’`, `’?’`, `’ ’`, `’λ’`.

    -   `Bool`: Represents boolean values, which can be either true or
        false.

        -   **Examples**: `True`, `False`.

    -   `Float`: Represents single-precision floating-point numbers, as
        specified by the IEEE standard.

        -   **Examples**: `3.14`, `-2.0`, `0.0`, `1.2e6`, `-0.5`.

    -   `String`: Represents sequences of characters. In Haskell,
        `String` is actually a synonym for `[Char]`, meaning a list of
        characters.

        -   **Example**: `"hello"`, `"Haskell"`, `""` (the empty
            string).

-   **Function Types**: These types describe functions. A function type
    specifies the type of input(s) and the type of the output.

    -   `Int -> Char`: This is the type of a function that takes a
        single argument of type `Int` and returns a value of type
        `Char`.

        -   **Example**: A function that converts an integer
            representing an ASCII code to its corresponding character
            would have this type.

    -   `a -> b`: This is a polymorphic function type. Here, `a` and `b`
        are type variables. This type represents a function that takes
        an argument of some type `a` and returns a value of some type
        `b`, where `a` and `b` can be any types. This is a powerful
        concept that allows for writing functions that are generic
        across many types.

-   **Structured Types**: These are composite types built from other
    types. They allow us to represent collections or combinations of
    data.

    -   `[Int]`: Represents a list where all elements are of type `Int`.
        Lists in Haskell are homogeneous, meaning all elements must be
        of the same type.

        -   **Examples**: `[1, 2, 3]`, `[]` (the empty list),
            `[5, -5, 0]`.

    -   `(Char, Int)`: Represents a pair, also known as a 2-tuple. This
        type combines a `Char` and an `Int`. Tuples can hold a fixed
        number of elements of potentially different types.

        -   **Examples**: `(’a’, 1)`, `(’z’, 26)`, `(’?’, 0)`.

    -   `(Bool, String, Char, Int)`: Represents a 4-tuple, combining a
        `Bool`, a `String`, a `Char`, and an `Int`. Haskell supports
        tuples of arbitrary finite length.

        -   **Example**: `(True, "hello", ’b’, 4)`.

## Type Annotations

In Haskell, we use the double colon `::` to assert or declare the type
of an expression. This is known as a **type annotation**. Type
annotations have the form `expression :: Type`.

Here are examples of type annotations using the types we have discussed:

    5             :: Int         -- The integer literal 5 has type Int
    'a'           :: Char        -- The character literal 'a' has type Char
    [1,2,3]       :: [Int]       -- The list [1,2,3] has type list of Int
    "hello"       :: String      -- The string literal "hello" has type String
    ('b', 4)      :: (Char, Int) -- The pair ('b', 4) has type pair of Char and Int
    (True, "hello", 'b', 4) :: (Bool, String, Char, Int) -- A 4-tuple with a specified type

The notation `expression :: Type` is read as \"expression has type
Type\". Type annotations are not just comments; they are checked by the
compiler. If the declared type does not match the type inferred by
Haskell, a compilation error will occur.

::: tcolorbox
**Attention:** Haskell's lexical syntax is **case-sensitive**,
especially concerning type identifiers.

-   **Type identifiers** must always begin with an **uppercase** letter.
    Examples include `Int`, `Char`, `String`, `Bool`, `Float`.

-   **Identifiers for values and functions** should start with a
    **lowercase** letter. Examples include `add`, `inc`, `fact`,
    `myValue`.

This distinction is crucial and must be adhered to when writing Haskell
code to avoid syntax errors.
:::

# Polymorphic Types

Haskell's type system is significantly enhanced by the inclusion of
**polymorphic types**. Polymorphism, in general, allows a single piece
of code to work with values of multiple types. In Haskell, we
specifically use **parametric polymorphism**, often just referred to as
polymorphism, which is a powerful feature that greatly increases code
reusability and flexibility.

## Parametric Polymorphism

::: definition
**Definition 1**. **Parametric polymorphism** allows us to write
functions and define data structures that are generic over types.
Instead of writing separate code for each specific type, we can write
one piece of code that operates uniformly on a range of types. This is
achieved through the use of **type variables** in type signatures.
:::

A **polymorphic type expression** describes a family of types. Consider
the example of `[a]`. This type expression represents the family of
\"list of `t`\" for every possible type `t`. Thus, `[a]` is not a single
concrete type, but rather a blueprint for creating types such as:

-   `[Int]` (list of integers)

-   `[Char]` (list of characters)

-   `[String]` (list of strings)

-   `[[Int]]` (list of lists of integers)

-   and many more\...

All of these are instances of the polymorphic type `[a]`. Here, `a` is a
**type variable**, acting as a placeholder for any concrete type.

**Type variables** are identifiers, typically single lowercase letters
like `a`, `b`, `c`, etc., used in type expressions to stand for
arbitrary types. By convention, they are uncapitalized. When a
polymorphic function is used, the type variable is instantiated with a
concrete type based on the context of use.

Many of Haskell's built-in functions and data structures are
polymorphic. This is a key reason for Haskell's expressiveness and the
high degree of code reuse it offers. Polymorphism allows us to write
functions that are not tied to specific types, making them applicable in
a broader range of situations.

For example, consider a function that returns the first element of a
list. In Haskell, this is the built-in function `head`. Its type
signature is `head :: [a] -> a`. Let's break down what this type
signature means:

-   `head` is the name of the function.

-   `::` denotes \"has the type\".

-   `[a] -> a` is the polymorphic type signature.

    -   `[a]` indicates that `head` takes a list as an argument, where
        the elements of the list are of type `a` (which can be any
        type).

    -   `->` signifies a function type, mapping the input type to the
        output type.

    -   `a` indicates that `head` returns a value of the same type `a`
        as the elements in the input list.

This polymorphic type signature tells us that `head` can operate on a
list of integers, a list of characters, or a list of any other type, and
it will always return an element of that same type.

## List Notation and Polymorphism in Practice

In Haskell, the convenient list notation `[1,2,3]` is actually syntactic
sugar. It is a more readable way of writing the expression
`1:(2:(3:[]))`. Understanding this desugaring is crucial for grasping
how lists are constructed and how polymorphism applies to them. Let's
dissect this:

-   `[]` represents the **empty list**. Its type is `[a]`, which is a
    polymorphic list type. This means the empty list can be considered a
    list of any type. It's the base case for list construction.

-   `:` is the **cons operator** (short for \"construct\"). It is an
    infix operator in Haskell, pronounced \"cons\". The cons operator is
    fundamental for building lists. Its type is `a -> [a] -> [a]`. This
    type signature is also polymorphic:

    -   `a` is the type of the element to be added to the front of the
        list.

    -   `[a]` (the second argument) is the type of the list to which the
        element is prepended.

    -   `[a]` (the result type) is the type of the new list created
        after prepending the element.

Therefore, the expression `x : xs` takes an element `x` of type `a` and
a list `xs` of type `[a]`, and it returns a new list of type `[a]` with
`x` at the beginning, followed by the elements of `xs`.

Let's illustrate with examples:

-   `1 : []` results in `[1]`, a list of integers. Here, `a` is
    instantiated to `Int`.

-   `’a’ : [’b’, ’c’]` results in `[’a’, ’b’, ’c’]`, a list of
    characters. Here, `a` is instantiated to `Char`.

-   `True : [False]` results in `[True, False]`, a list of booleans.
    Here, `a` is instantiated to `Bool`.

The list `[1, 2, 3]` is thus constructed step-by-step:

1.  Start with the empty list: `[]` (which is of type `[a]`)

2.  Prepend `3`: `3 : []` results in `[3]` (of type `[Int]`)

3.  Prepend `2`: `2 : [3]` results in `[2, 3]` (of type `[Int]`)

4.  Prepend `1`: `1 : [2, 3]` results in `[1, 2, 3]` (of type `[Int]`)

Consider again the `head` and `tail` functions we saw earlier:

    head :: [a] -> a
    head (x:xs) = x

    tail :: [a] -> [a]
    tail (x:xs) = xs

These functions utilize pattern matching on the list structure. The
pattern `(x:xs)` matches any non-empty list, binding `x` to the first
element (head) and `xs` to the rest of the list (tail).

::: example
**Example 1**. Examples of polymorphic behavior of `head` and `tail`:

-   `head [1, 2]` is evaluated as `head (1:(2:[]))`, which matches the
    pattern `(x:xs)` with `x = 1` and `xs = [2]`. It returns `x`, which
    is `1` (an `Int`).

-   `tail [1, 2]` is evaluated as `tail (1:(2:[]))`, which again matches
    `(x:xs)` with `x = 1` and `xs = [2]`. It returns `xs`, which is
    `[2]` (a list of `Int`, i.e., `[Int]`).
:::

The polymorphism of `head` and `tail` is evident as they operate
seamlessly on lists of any type, always adhering to their polymorphic
type signatures. This exemplifies the power and elegance of parametric
polymorphism in Haskell.

# Functions

Functions are fundamental building blocks in Haskell. In Haskell,
functions are defined primarily through **equations**. A set of these
equations constitutes a **function declaration**.

## Function Declarations

Function declarations in Haskell specify how a function behaves for
different inputs. Let's look at some examples to understand how
functions are declared.

### Increment Function

::: example
**Example 2**. To define a function named `inc` that increments a number
by one, we write:

    inc x = x + 1

This single equation is a complete function declaration for `inc`. It
states that when `inc` is applied to an argument `x`, the result is the
value of `x + 1`.
:::

### Factorial Function

::: example
**Example 3**. For a more complex example, consider the factorial
function. The factorial function is typically defined recursively. In
Haskell, we can define it using multiple equations to handle different
cases:

    fact 0 = 1
    fact n = n * fact (n-1)

This declaration consists of two equations:

-   The first equation, `fact 0 = 1`, is the **base case**. It specifies
    that the factorial of `0` is `1`.

-   The second equation, `fact n = n * fact (n-1)`, is the **recursive
    case**. It defines the factorial of any number `n` (implicitly
    assumed to be positive in this context) as `n` multiplied by the
    factorial of `n-1`.

When `fact` is called, Haskell will try to match the input with the
equations in the order they are written. If the input is `0`, the first
equation is matched, and the result is `1`. If the input is any other
number `n`, the second equation is matched, and the factorial is
computed recursively.
:::

### Combination Function

::: example
**Example 4**. As another example, let's define a function to calculate
combinations, often denoted as \"n choose k\", which is the number of
ways to choose `k` items from a set of `n` items. Mathematically, it's
given by $\binom{n}{k} = \frac{n!}{k!(n-k)!}$. Assuming we have already
defined the factorial function `fact`, we can define a combination
function `comb` as:

    comb n k = fact n `div` fact k `div` fact (n-k)

In this definition, `‘div‘` is used for integer division in Haskell and
is used in infix notation by enclosing it in backticks. This equation
directly implements the mathematical formula for combinations using the
`fact` function.
:::

## Type Signature Declarations

While Haskell's type inference can often deduce the types of functions,
it is excellent practice to explicitly declare the types of functions
using **type signature declarations**. A type signature declaration
specifies the type of a function, making the code more readable and
helping to catch type errors at compile time.

For the `inc` and `fact` functions defined above, we can add type
signatures as follows:

    inc  :: Int -> Int
    inc x = x + 1

    fact :: Int -> Int
    fact 0 = 1
    fact n = n * fact (n-1)

The line `inc :: Int -> Int` is a type signature declaration for `inc`.
It states that `inc` is a function that takes an argument of type `Int`
and returns a result of type `Int`. Similarly, `fact :: Int -> Int`
declares that `fact` is also a function from `Int` to `Int`.

Type signatures are not mandatory in many cases due to Haskell's type
inference, but they are highly recommended for:

-   **Documentation**: Type signatures clearly communicate the intended
    type of a function, making it easier to understand the function's
    purpose and usage.

-   **Error Detection**: If the implemented function does not conform to
    its declared type signature, the Haskell compiler will report a type
    error. This helps in catching mistakes early in the development
    process.

-   **Clarity in Complex Types**: For functions with more complex types,
    especially higher-order functions or polymorphic functions, type
    signatures can significantly improve readability.

By using type signatures, you make your Haskell code more robust,
maintainable, and easier to understand for yourself and others.

# Curried and Uncurried Functions

In Haskell, understanding the concept of curried versus uncurried
functions is crucial. By default, functions in Haskell are **curried**,
a design choice that profoundly influences how functions are defined and
applied.

## Curried Functions

::: definition
**Definition 2**. Consider the following definition of a function `add`
that sums two numbers:

    add :: Int -> Int -> Int
    add x y = x + y

This is the **curried** form of the `add` function. The type signature
`Int -> (Int -> Int)` reveals its curried nature. It indicates that
`add` is a function that takes an `Int` and returns *another function*
(`Int -> Int`). This returned function then takes an `Int` and finally
returns an `Int` as the result.
:::

In practice, when we apply `add` to two arguments, say `5` and `3`, the
process unfolds as follows:

1.  **Partial Application**: Applying `add` to just the first argument,
    `5`, i.e., `add 5`, does not compute the final sum. Instead, it
    returns a *new function*. This new function is specialized to add
    `5` to its argument. The type of `(add 5)` is `Int -> Int`.

2.  **Second Application**: This new function is then applied to the
    second argument, `3`, i.e., `(add 5) 3`. This completes the
    computation, resulting in `8`.

Thus, a curried function processes its arguments one at a time,
returning a new function at each step until all arguments are provided,
at which point it computes the final value. This approach is fundamental
to functional programming and enables powerful techniques like partial
application and function composition.

## Uncurried Functions

::: definition
**Definition 3**. In contrast to curried functions, **uncurried**
functions take all their arguments at once, typically as a tuple. We can
define an uncurried version of the addition function as:

    add' :: (Int, Int) -> Int
    add' (x,y) = x + y

Here, the type signature `(Int, Int) -> Int` clearly shows that `add’`
takes a single argument, which is a pair `(Int, Int)`. When we call
`add’`, we must provide a pair: `add’ (5, 3)`, which directly returns
`8`.

The key difference is that `add’` expects both numbers to be provided as
a single tuple argument, whereas `add` accepts them sequentially,
enabling partial application.
:::

## Function Application and Type Constructor Associativity

Understanding associativity is crucial for correctly interpreting
Haskell syntax, especially function application and type signatures.

### Function Application: Left-Associative

::: remark
**Remark 1**. Function application in Haskell is **left-associative**.
This means that when you have a sequence of function applications like
`f e1 e2 e3`, it is parsed as if parenthesized from the left:
`((f e1) e2) e3`.

For example, with our curried `add` function, `add 5 3` is interpreted
as `(add 5) 3`. First, `add` is applied to `5`, resulting in a function
`(add 5)`. Then, this resulting function is applied to `3`.
:::

### Function Type Constructor: Right-Associative

::: remark
**Remark 2**. In contrast, the function type constructor `->` is
**right-associative**. This affects how type signatures are parsed. A
type like `Int -> Int -> Int` is parsed as `Int -> (Int -> Int)`.

This right-associativity is consistent with the concept of currying.
`Int -> Int -> Int` represents a function that takes an `Int` and
returns a function of type `Int -> Int`, which in turn takes an `Int`
and returns an `Int`.
:::

::: mdframed
**Summary of Associativity:**

-   **Function Application** is **left-associative**: `f e1 e2` $\equiv$
    `(f e1) e2`

-   **Function Type Constructor** (`->`) is **right-associative**:
    `T1 -> T2 -> T3` $\equiv$ `T1 -> (T2 -> T3)`

This combination of left-associativity for application and
right-associativity for the type constructor is what makes currying a
natural and seamless feature of Haskell.
:::

# Examples of Polymorphic Functions

To solidify our understanding of polymorphic types, let"s explore some
built-in Haskell functions that exemplify polymorphism in action. We
will look at the functions `head`, `tail`, and `length`, all of which
operate on lists but are not restricted to lists of a specific type.

    head :: [a] -> a
    head (x:xs) = x

    tail :: [a] -> [a]
    tail (x:xs) = xs

    length :: [a] -> Int
    length []     = 0
    length (x:xs) = 1 + length xs

## Polymorphism in Type Signatures

Observe the type signatures of these functions. Each of them includes
the type variable `a` within their type definitions, making them
**polymorphic**. This means they are not limited to operating on lists
of integers, characters, or any other single specific type; they can
work with lists containing elements of *any* type.

-   `head :: [a] -> a`: This signature indicates that `head` is a
    function that takes a list of type `[a]` (a list of elements of some
    type `a`) and returns a single element of type `a`. The crucial
    point is that `a` can be any type.

-   `tail :: [a] -> [a]`: Similarly, `tail` takes a list of type `[a]`
    and returns another list of type `[a]`. It returns the remainder of
    the list after removing the first element, maintaining the element
    type.

-   `length :: [a] -> Int`: The `length` function takes a list of type
    `[a]` and returns an `Int`. It counts the number of elements in the
    list, irrespective of the element type.

## Pattern Matching in Function Definitions

The function definitions themselves utilize **pattern matching** on the
structure of lists. Pattern matching is a powerful feature in Haskell
that allows functions to be defined by cases based on the form oftheir
input arguments.

Let's break down the patterns used:

-   `[]`: This pattern matches specifically against the **empty list**.
    In the definition of `length`, `length [] = 0` states that when
    `length` is applied to an empty list, it returns `0`.

-   `(x:xs)`: This pattern matches against **non-empty lists**. It
    deconstructs a non-empty list into two parts:

    -   `x`: Bound to the **head** (the first element) of the list.

    -   `xs`: Bound to the **tail** (the rest of the list, which is
        itself a list) of the list.

    In `head (x:xs) = x`, when `head` is applied to a non-empty list, it
    matches this pattern, and the function returns `x`, the head of the
    list. Similarly, `tail (x:xs) = xs` returns `xs`, the tail of the
    list. For `length (x:xs) = 1 + length xs`, it recursively calculates
    the length by adding 1 (for the head element `x`) to the length of
    the tail `xs`.

## Illustrative Examples

::: tcolorbox
Let's see these polymorphic functions in action with different types of
lists:

-   **Using `head`**

    -   `head [1, 2]` : Here, `head` is applied to a list of integers.
        The list `[1, 2]` matches the pattern `(x:xs)` with `x` bound to
        `1` and `xs` bound to `[2]`. The function returns `x`, which is
        `1`. Thus, `head [1, 2]` evaluates to `1`.

    -   `head `$$'a', 'b', 'c'$$ : Applied to a list of characters,
        `head` still works. `x` becomes `’a’` and `xs` becomes
        `[’b’, ’c’]`. `head `$$'a', 'b', 'c'$$ evaluates to `’a’`.

-   **Using `tail`**

    -   `tail [1, 2]` : For the integer list, `tail` returns the rest of
        the list after the head. `tail [1, 2]` evaluates to `[2]`.

    -   `tail `$$'a', 'b', 'c'$$ : For the character list, `tail`
        similarly returns the tail. `tail `$$'a', 'b', 'c'$$ evaluates
        to `[’b’, ’c’]`.

-   **Using `length`**

    -   `length [1, 2, 3, 4]` : Counts the elements in the integer list.
        `length [1, 2, 3, 4]` evaluates to `4`.

    -   `length `$$"apple", "banana", "cherry"$$ : Counts the elements
        in a list of strings. `length `$$"apple", "banana", "cherry"$$
        evaluates to `3`.

    -   `length []` : For the empty list, it matches the `[]` pattern
        and returns `0`. `length []` evaluates to `0`.

These examples demonstrate that `head`, `tail`, and `length` are indeed
polymorphic. They operate uniformly on lists regardless of the type of
elements contained within them, adhering to their respective polymorphic
type signatures. This exemplifies the power and elegance of parametric
polymorphism in Haskell.
:::

# Higher-Order Functions

::: definition
**Definition 4** (Higher-Order Functions). **Higher-order functions**
are a distinguishing feature of functional programming languages like
Haskell. They are functions that operate on other functions, either by
taking one or more functions as arguments or by returning a function as
a result. This capability elevates functions to first-class citizens in
the language, allowing for powerful abstractions and code reuse.

In Haskell, curried functions are inherently higher-order because when
you partially apply a curried function, you get another function as a
result.
:::

Let's explore some fundamental higher-order functions in Haskell: `map`,
`foldr`, and `foldl`.

    map :: (a -> b) -> [a] -> [b]
    map f []     = []
    map f (x:xs) = f x : map f xs

    foldr :: (a -> b -> b) -> b -> [a] -> b
    foldr f z (x:xs) = f x (foldr f z xs)
    foldr f z []     = z

    foldl :: (b -> a -> b) -> b -> [a] -> b
    foldl f z (x:xs) = foldl f (f z x) xs
    foldl f z []     = z

## The `map` Function

::: definition
**Definition 5** (The map Function). The `map` function is used to apply
a given function to each element of a list, producing a new list
containing the results.
:::

### Type Signature and Definition

`map :: (a -> b) -> [a] -> [b]`

-   `(a -> b)`: The first argument is a function, let's call it `f`,
    that takes a value of type `a` and returns a value of type `b`.

-   `[a]`: The second argument is a list of type `[a]`, i.e., a list of
    elements of type `a`.

-   `[b]`: The return type is a list of type `[b]`, a list of elements
    of type `b`.

The definition of `map` is given by two equations, again using pattern
matching:

    map f []     = []
    map f (x:xs) = f x : map f xs

-   **Base Case**: `map f [] = []` - When `map` is applied to an empty
    list ( `[]` ), it returns an empty list. This is the terminating
    condition for the recursion.

-   **Recursive Step**: `map f (x:xs) = f x : map f xs` - When `map` is
    applied to a non-empty list `(x:xs)`, it does two things:

    1.  Applies the function `f` to the head element `x` to get `f x`.

    2.  Recursively calls `map f xs` to process the rest of the list
        `xs`.

    3.  Constructs a new list by prepending `(f x)` to the result of the
        recursive call `(map f xs)` using the cons operator `:`.

### Example Usage of `map`

Let's define a simple increment function `inc`:

    inc x = x + 1

::: tcolorbox
Now, let's use `map` with `inc` to increment every element in a list of
numbers:

    expression: map inc [1,2,3]

This expression evaluates to `[2,3,4]`. Here's how it works
step-by-step:

1.  `map inc [1, 2, 3]`

2.  `inc 1 : map inc [2, 3]` (applying the recursive step)

3.  `2 : map inc [2, 3]` ( `inc 1` evaluates to `2` )

4.  `2 : (inc 2 : map inc [3])` (recursive step again)

5.  `2 : (3 : map inc [3])` ( `inc 2` evaluates to `3` )

6.  `2 : (3 : (inc 3 : map inc []))` (one more recursive step)

7.  `2 : (3 : (4 : map inc []))` ( `inc 3` evaluates to `4` )

8.  `2 : (3 : (4 : []))` ( `map inc []` evaluates to `[]` - base case)

9.  `[2, 3, 4]` (list construction)
:::

## The `foldl` Function (Fold Left)

::: definition
**Definition 6** (The foldl Function). The `foldl` function, short for
\"fold left\", is another powerful higher-order function used to combine
the elements of a list into a single value. It does this by applying a
binary function cumulatively from left to right.
:::

### Type Signature and Definition

`foldl :: (b -> a -> b) -> b -> [a] -> b`

-   `(b -> a -> b)`: The first argument is a binary function, let's call
    it `f`, that takes two arguments: an accumulator of type `b` and an
    element of type `a`, and returns a new accumulator of type `b`.

-   `b`: The second argument is the initial value of the accumulator,
    often called the \"base case\" or \"zero case\", of type `b`.

-   `[a]`: The third argument is the input list of type `[a]`.

-   `b`: The return type is the final accumulated value of type `b`.

The definition of `foldl` is:

    foldl f z (x:xs) = foldl f (f z x) xs
    foldl f z []     = z

-   **Base Case**: `foldl f z [] = z` - When `foldl` is applied to an
    empty list, it returns the initial accumulator value `z`.

-   **Recursive Step**: `foldl f z (x:xs) = foldl f (f z x) xs` - For a
    non-empty list `(x:xs)`, `foldl` does the following:

    1.  Applies the binary function `f` to the current accumulator `z`
        and the head element `x` to get a new accumulator `(f z x)`.

    2.  Recursively calls `foldl` with the new accumulator `(f z x)` and
        the tail of the list `xs`.

### Example Usage of `foldl`

Let's use `foldl` to sum the elements of a list, starting with an
initial sum of `10`. We'll assume `add` is our curried addition function
from before.

::: tcolorbox
    expression: foldl add 10 [1,2,3]

This expression evaluates to `16`. Let's trace the evaluation:

1.  `foldl add 10 [1, 2, 3]`

2.  `foldl add (add 10 1) [2, 3]` (apply `add` to initial accumulator
    `10` and head `1`)

3.  `foldl add (10 + 1) [2, 3]` (evaluate `add 10 1` to `11`)

4.  `foldl add 11 [2, 3]` (simplified accumulator)

5.  `foldl add (add 11 2) [3]` (apply `add` to current accumulator `11`
    and head `2`)

6.  `foldl add (11 + 2) [3]` (evaluate `add 11 2` to `13`)

7.  `foldl add 13 [3]` (simplified accumulator)

8.  `foldl add (add 13 3) []` (apply `add` to current accumulator `13`
    and head `3`)

9.  `foldl add (13 + 3) []` (evaluate `add 13 3` to `16`)

10. `foldl add 16 []` (simplified accumulator)

11. `16` (base case: empty list, return current accumulator `16`)

Thus, `foldl add 10 [1, 2, 3]` results in `16`, which is
`10 + 1 + 2 + 3`.
:::

## The `foldr` Function (Fold Right)

::: definition
**Definition 7** (The foldr Function). The `foldr` function, or \"fold
right\", is similar to `foldl` but it processes the list from right to
left. It's often more conceptually aligned with recursive list
processing in functional programming.
:::

### Type Signature and Definition

`foldr :: (a -> b -> b) -> b -> [a] -> b` The type signature of `foldr`
is the same as `foldl`, but its behavior is different.

    foldr f z (x:xs) = f x (foldr f z xs)
    foldr f z []     = z

-   **Base Case**: `foldr f z [] = z` - Just like `foldl`, for an empty
    list, `foldr` returns the initial value `z`.

-   **Recursive Step**: `foldr f z (x:xs) = f x (foldr f z xs)` - For a
    non-empty list `(x:xs)`, `foldr` does:

    1.  Recursively calls `foldr f z xs` on the tail `xs` to process the
        rest of the list *first*. Let's say the result of this recursive
        call is `recursive_result`.

    2.  Applies the binary function `f` to the head element `x` and the
        `recursive_result` to get the final result
        `(f x recursive_result)`.

Notice how in `foldr`, the function `f` is applied to the current
element `x` and the result of folding the *rest* of the list,
contrasting with `foldl` where `f` is applied to the accumulator and the
current element.

::: remark
**Remark 3** (Conceptual Difference between foldl and foldr).

### Conceptual Difference between `foldl` and `foldr`

-   `foldl` is typically iterative in nature, accumulating a result from
    left to right. It's often more efficient in strict languages for
    simple accumulations but can be less efficient with lazy evaluation
    for certain operations.

-   `foldr` is more naturally recursive and works from right to left.
    It's particularly well-suited for operations that can benefit from
    lazy evaluation and for preserving list structure in
    transformations. For many operations in Haskell, `foldr` is
    considered more idiomatic and sometimes more efficient due to
    laziness.
:::

## Summary

Higher-order functions like `map`, `foldl`, and `foldr` are essential
tools in functional programming. They allow for abstracting common
patterns of computation over lists and other data structures, leading to
more concise, reusable, and expressive code. Understanding and
effectively using these functions is a key step in mastering functional
programming in Haskell.

# Partial Application of Curried Functions

::: definition
**Definition 8** (Partial Application). One of the most powerful
features enabled by currying in Haskell is **partial application**.
Partial application allows you to apply a function to fewer arguments
than it is designed to accept. The result is a new function that is
waiting for the remaining arguments. This technique is incredibly useful
for creating specialized functions from more general ones and for
enhancing code conciseness and readability.
:::

## Basic Partial Application

::: example
**Example 5** (Basic Partial Application of add function). Consider our
familiar curried addition function, `add`:

    add :: Int -> Int -> Int
    add x y = x + y

We can create a new function, say `inc`, which increments a number by
one, by partially applying `add` with the first argument set to `1`:

    inc = add 1

Here, `inc` is not a value but a *function*. By providing only the first
argument (`1`) to `add`, we've created a specialized version of `add`.
The function `inc` now has the type `Int -> Int`. It's a function that
is \"waiting\" for one more `Int` argument to complete the addition.

When we call `inc` with an argument, say `5`:

    inc 5

This is equivalent to `(add 1) 5`, which then evaluates to `1 + 5 = 6`.
:::

## Partial Application with Higher-Order Functions

::: example
**Example 6** (Partial Application with Higher-Order Functions (map)).
Partial application becomes even more potent when combined with
higher-order functions. Let's revisit the `map` function:

    map :: (a -> b) -> [a] -> [b]

Suppose we want to increment every number in a list by 1. Instead of
defining a separate named function and then using `map`, we can directly
use partial application with `add` within `map`:

    map (add 1) [1,2,3]

This elegantly applies the \"increment by 1\" operation to each element
of the list `[1,2,3]`. The expression `(add 1)` is a partially applied
function, which is then passed as the first argument to `map`. `map`
then applies this partially applied function to each element of the
list, resulting in `[2,3,4]`.
:::

## Example with Combination Function

::: example
**Example 7** (Partial Application with Combination Function). Let's
consider the combination function `comb` we defined earlier:

    comb n k = fact n `div` fact k `div` fact (n-k)

Suppose we want to calculate the number of combinations when choosing
`k` items from a fixed set of `4` items, for various values of `k`. We
can create a function that is specialized for `n = 4` by partially
applying `comb`:

    combFrom4 = comb 4

Now, `combFrom4` is a function of type `Int -> Int`. It takes one
argument `k` and calculates \"4 choose k\". We can use this partially
applied function with `map` to calculate combinations for a range of `k`
values:

    map combFrom4 [0,1,2,3,4]

or more directly, without defining `combFrom4`:

    map (comb 4) [0,1,2,3,4]

This expression evaluates to `[1, 4, 6, 4, 1]`, which are the binomial
coefficients
$\binom{4}{0}, \binom{4}{1}, \binom{4}{2}, \binom{4}{3}, \binom{4}{4}$.
:::

::: remark
**Remark 4** (Benefits of Partial Application).

## Benefits of Partial Application

-   **Code Reusability**: Create specialized functions from general
    ones, avoiding redundant code.

-   **Readability**: Express complex operations more clearly by breaking
    them down into simpler, partially applied functions.

-   **Flexibility**: Easily adapt functions to different contexts by
    fixing some arguments and leaving others open.

-   **Composition**: Facilitates function composition and point-free
    style programming, leading to more elegant and concise code.

Partial application is a cornerstone of functional programming in
Haskell, enabling a highly flexible and expressive coding style. It
encourages building programs by composing and specializing functions,
leading to more modular and maintainable code.
:::

# Lambda Abstractions

::: definition
**Definition 9** (Lambda Abstractions). In Haskell, functions are not
only defined and named but can also be expressed as anonymous entities
directly within expressions. This is achieved through **lambda
abstractions**. Lambda abstractions are essentially unnamed functions,
defined inline where they are needed. They are a powerful tool for
creating functions on-the-fly, especially for higher-order functions.
:::

## Syntax and Basic Examples

The syntax for a lambda abstraction in Haskell is:

    \arguments -> body

Here:

-   `\` (backslash) symbol initiates a lambda abstraction. It's used
    because it resembles the Greek letter lambda (λ), which is
    traditionally used in lambda calculus to denote anonymous functions.

-   `arguments` is a space-separated list of argument names. These are
    the parameters of the anonymous function.

-   `->` separates the arguments from the function body.

-   `body` is the expression that defines the function's computation.
    It's the code that will be executed when the anonymous function is
    applied.

::: example
**Example 8** (Basic Examples of Lambda Abstractions). Let's look at
some examples to illustrate lambda abstractions:

-   **Function to add 3 to its argument**:

            \x -> x + 3

    This lambda abstraction defines a function that takes one argument,
    named `x`, and returns the result of `x + 3`. It's an anonymous
    equivalent to writing a named function like `add3 x = x + 3`.

-   **Curried function to add two arguments**:

            \x -> \y -> x + y

    This defines a curried function that takes two arguments. It's a
    lambda abstraction that, when given an argument `x`, returns
    *another* lambda abstraction `\y -> x + y`. This inner lambda
    abstraction takes an argument `y` and returns `x + y`. This is
    equivalent to our named curried `add` function.

-   **Concise syntax for curried functions**:

            \x y -> x + y

    Haskell provides a more concise syntax for curried lambda
    abstractions with multiple arguments. `\x y -> x + y` is equivalent
    to `\x -> \y -> x + y`. It's a shorthand for defining curried
    functions that take multiple arguments.
:::

## Usage with Higher-Order Functions

::: example
**Example 9** (Usage of Lambda Abstractions with Higher-Order Functions
(map)). Lambda abstractions are particularly useful when you need to
pass a simple, often one-time-use function as an argument to a
higher-order function. They eliminate the need to define a separate
named function in such cases, making the code more compact and focused.

Consider using `map` to multiply each element in a list by 3. Instead of
defining a separate function like `multiplyBy3` and then passing it to
`map`, we can use a lambda abstraction directly:

    map (\x -> 3*x) [1,2,3]

In this expression, `(\x -> 3*x)` is a lambda abstraction. It's an
anonymous function that takes an argument `x` and returns `3*x`. This
anonymous function is directly passed as the first argument to `map`.
`map` then applies this function to each element of the list `[1,2,3]`,
resulting in `[3,6,9]`.
:::

::: remark
**Remark 5** (Advantages of Lambda Abstractions).

## Advantages of Lambda Abstractions

-   **Anonymity**: Define functions without needing to name them, which
    is useful for functions that are used only once or in a localized
    context.

-   **Inline Function Definition**: Define functions directly within
    expressions, making the code more concise and often more readable by
    keeping related code together.

-   **Flexibility with Higher-Order Functions**: Easily create and pass
    function arguments to higher-order functions without clutteringthe
    code with many auxiliary named function definitions.

-   **Expressiveness**: Enhance the expressiveness of Haskell code by
    allowing functions to be treated as first-class, inline values.

Lambda abstractions are a vital feature in Haskell and functional
programming in general. They promote a style of programming where
functions are treated as values that can be created, passed around, and
used just like any other data, leading to more flexible and expressive
code.
:::

# Infix Operators

::: definition
**Definition 10** (Infix Operators). In Haskell, operators like `+`,
`*`, `:`, `++`, and `.` are not special syntactic constructs but are
actually just **functions**. The term \"infix\" refers to their
syntactic placement *between* their operands, as opposed to prefix
functions which appear before their arguments. This infix notation is
primarily for convenience and readability, especially for operations
that are naturally binary.
:::

## Operators as Functions

In Haskell, almost anything that looks like an operator is indeed a
function. This means that infix operators can be defined and used just
like any other function. They can be defined using equations, and they
have types.

### Example: List Concatenation Operator `++`

::: example
**Example 10** (List Concatenation Operator ++). The list concatenation
operator `++` is a prime example. It's used to join two lists together.
We can define its behavior using equations, just like any other
function:

    []     ++ ys = ys
    (x:xs) ++ ys = x : (xs ++ ys)

These equations define how `++` behaves:

-   When the first list is empty (`[]`), concatenating it with any list
    `ys` results in `ys` itself (the first equation).

-   When the first list is non-empty `(x:xs)`, concatenating it with
    `ys` results in a new list that starts with the head `x` of the
    first list, followed by the concatenation of the tail `xs` and the
    list `ys` (the second equation, which is recursive).

This definition is no different from how we might define any other
recursive function in Haskell. The only distinction is that `++` is used
as an infix operator.
:::

### Example: Function Composition Operator `.`

::: example
**Example 11** (Function Composition Operator .). Another crucial
operator in functional programming is the function composition operator
`.` (dot). It's used to compose two functions, meaning applying one
function to the result of another. Its definition is:

    f . g = \x -> f (g x)

This equation defines the composition of two functions `f` and `g`.
`(f . g)` results in a new function (a lambda abstraction) that takes an
argument `x`, applies `g` to `x` first, and then applies `f` to the
result of `(g x)`.
:::

## Lexical Nature of Infix Operators

::: remark
**Remark 6** (Lexical Nature of Infix Operators). Lexically, infix
operators in Haskell are typically distinguished by being composed
entirely of symbols, rather than alphanumeric characters. Common symbols
used in operators include:

    +, -, *, /, $, !, @, %, ^, &, |, <, >, =, ?, ., :, ++, **, >>, <<, ...

For instance, `+`, `*`, `++`, `::`, `.`, `$` are all infix operators.
Identifiers composed of letters and digits, typically starting with a
lowercase letter, are usually treated as prefix function names.
:::

## Using Operators as Prefix Functions

Since operators are functions, and functions in Haskell are first-class,
we can also use operators in a prefix manner, just like regular
functions. To do this, we enclose the operator in parentheses.

For example, `+` is an infix operator for addition. Infix usage:
`3 + 4`. Prefix usage: `(+) 3 4`. Both expressions are equivalent and
evaluate to `7`.

This prefix notation is particularly useful when you want to pass an
operator as an argument to a higher-order function, or when you want to
partially apply an operator. For example, to increment every element in
a list using `map` and the addition operator, you can write:

    map ((+) 1) [1,2,3]  -- Evaluates to [2,3,4]

Here, `((+) 1)` is a partial application of the prefix version of the
`+` operator. It creates a function that adds `1` to its argument.

## Custom Infix Operators

::: remark
**Remark 7** (Custom Infix Operators). Haskell allows you to define your
own infix operators. You can create new operators composed of symbols
and define their precedence and associativity if needed (though we won't
delve into precedence and associativity rules here). Defining custom
operators can be useful for creating domain-specific languages or for
mathematical or symbolic computations where infix notation is
conventional and enhances readability.
:::

In summary, infix operators in Haskell are simply functions with a
special syntax that allows them to be placed between their operands.
They are defined and used just like prefix functions, offering
flexibility in how you express operations, especially in mathematical
and list-processing contexts.

# Sections

::: definition
**Definition 11** (Sections). **Sections** in Haskell provide a concise
syntax for partially applying infix operators. Since infix operators are
just functions, sections allow us to create new functions by fixing one
of the arguments of an operator, making them very handy, especially when
working with higher-order functions.
:::

There are three main types of sections: left sections, right sections,
and operator sections.

## Left Sections

::: definition
**Definition 12** (Left Sections). A **left section** is created by
enclosing an infix operator and its left operand in parentheses. The
syntax is `(left_operand operator)`. This form creates a function that
takes one argument (the right operand) and applies the operator with the
specified left operand and the given operator.
:::

### Example: Incrementing by a Fixed Value

::: example
**Example 12** (Left Section Example: Incrementing by a Fixed Value).
Consider the addition operator `+`. A left section `(5+)` is equivalent
to the lambda abstraction `\y -> 5 + y`. It's a function that takes an
argument `y` and adds `5` to it. In essence, the left operand (`5`) is
fixed, and the section is waiting for the right operand.

    (5+) :: Num a => a -> a
    (5+) y = 5 + y

We can use this section with `map` to add 5 to each element of a list:

    map (5+) [1, 2, 3]  -- Evaluates to [6, 7, 8]
:::

## Right Sections

::: definition
**Definition 13** (Right Sections). A **right section** is formed by
enclosing an infix operator and its right operand in parentheses, like
`(operator right_operand)`. This creates a function that takes one
argument (the left operand) and applies the operator with the given
right operand.
:::

### Example: Dividing by a Fixed Value

::: example
**Example 13** (Right Section Example: Dividing by a Fixed Value). Using
the division operator `/`, a right section `(/2)` is equivalent to
`\x -> x / 2`. This function takes an argument `x` and divides it by
`2`. Here, the right operand (`2`) is fixed, and the section is waiting
for the left operand.

    (/2) :: Fractional a => a -> a
    (/2) x = x / 2

Example usage:

    map (/2) [4, 6, 8]  -- Evaluates to [2.0, 3.0, 4.0]
:::

## Operator Sections

::: definition
**Definition 14** (Operator Sections). An **operator section** consists
of just the infix operator enclosed in parentheses, like `(operator)`.
This form is used to treat a binary operator as a prefix function. It's
equivalent to a lambda abstraction that takes two arguments and applies
the operator to them.
:::

### Example: Using Addition as a Prefix Function

::: example
**Example 14** (Operator Section Example: Using Addition as a Prefix
Function). The operator section `(+)` is equivalent to `\x y -> x + y`.
It represents the binary addition operation as a standard prefix
function.

    (+) :: Num a => a -> a -> a
    (+) x y = x + y

This is particularly useful when you need to pass a binary operator to a
higher-order function that expects a function argument. For instance,
using `foldl` to sum up a list of numbers:

    foldl (+) 0 [1, 2, 3, 4]  -- Evaluates to 10

Here, `(+)` is passed as the combining function to `foldl`.
:::

## Coercing Binary Functions to Infix Operators

::: remark
**Remark 8** (Coercing Binary Functions to Infix Operators). Conversely,
if you have a binary function and you want to use it as an infix
operator, Haskell allows you to enclose the function name in backquotes
(").

For example, if we have a function `myAdd`:

    myAdd :: Int -> Int -> Int
    myAdd x y = x + y

We can use it in infix form like this:

    5 `myAdd` 3  -- Equivalent to myAdd 5 3, evaluates to 8

This backtick notation is handy for using named binary functions in an
infix style, which can sometimes improve readability, especially in
mathematical or domain-specific contexts.
:::

## Use Cases for Sections

::: remark
**Remark 9** (Use Cases for Sections). Sections are incredibly useful in
various scenarios:

-   **Concise Partial Application**: They provide a compact way to
    create partially applied functions from operators.

-   **Higher-Order Functions**: Sections are frequently used when
    passing operators as arguments to higher-order functions like `map`,
    `filter`, `foldl`, `foldr`, etc., leading to cleaner and more
    readable code.

-   **Readability**: For common operations, sections often make the
    intent of the code clearer and more immediate than using lambda
    abstractions.
:::

In summary, sections are a syntactic convenience in Haskell that
leverages the fact that operators are functions, allowing for elegant
partial application and enhancing the expressiveness of functional code,
especially when working with operators and higher-order functions.
